Testing de APIs en Cypress

◎¿Qué es una API?
API significa interfaz de programación de aplicaciones. Es la forma en que dos programas se hablan con reglas fijas: uno pide y el otro responde.
Comensal
Cliente
Hace el pedido.
Tu navegador, tu app o Cypress.
⇄
Mozo
API
Lleva el pedido y trae el plato. Solo entiende lo que está en la carta: los endpoints.
⇄
Cocina
Servidor
Prepara el plato: busca en la base de datos y arma la respuesta.
Un ejemplo real: cuando abrís la tienda, tu navegador le pide /products a la API y la API le devuelve la lista de herramientas.

AaGlosario express

  

  

    

      
API
El mozo: lleva tu pedido a la cocina y te trae el plato.

      
Endpoint
Una dirección concreta de la API, como /products. Un mostrador para algo puntual.

      
Request
El pedido: método + dirección y, a veces, datos.

      
Response
Lo que te devuelven: status, headers y body.

    

    

      
Método HTTP
El verbo del pedido: GET (leer), POST (crear), DELETE (borrar).

      
Header
Datos del sobre, como la etiqueta de un paquete. Ej: Authorization.

      
Body (payload)
El contenido del mensaje: los datos que mandás o recibís.

      
Status code
Número que dice cómo salió: 200 bien, 404 no existe, 500 se rompió.

    

    

      
JSON
Formato para ordenar datos con clave: valor. Es el idioma de las APIs.

      
Token
Una entrada digital: prueba que ya hiciste login. Dura poco.

      
Mock (stub)
Una respuesta falsa que controlás vos, como un actor de reemplazo en un simulacro.

      
Fixture
Archivo .json con datos de prueba guardado en cypress/fixtures.

    

  







  
Testing de APIs en Cypress

  
✔Errores comunes y buenas prácticas

  

  

    
Validá estructura, no valores
En una API pública los datos cambian. Chequeá que existan id y name, no un nombre exacto.

    
Pedí el token en cada test
Vence a los 300 segundos. Hacé el login en un beforeEach y no lo copies a mano.

    
Para errores, failOnStatusCode
Si esperás un 401 o un 404, poné failOnStatusCode: false o el test falla antes de validar.

    
No asumas el código
Esperábamos un 422 en el login sin datos y la API respondió 401. Mirá la respuesta real antes de escribir el test.

    
Datos falsos en los POST
Es un servidor público. Usá emails inventados y generá uno distinto en cada corrida.

    
Una idea por test
Un it() valida una cosa. Si falla, sabés exactamente qué se rompió.

  







  
Testing de APIs en Cypress

  
★Tu turno: 3 retos

  

    

      
Reto 1 · GET
/brands debe responder 200 con un array, y cada marca debe tener id, name y slug.

      

    

    

      
Reto 2 · 404
Un producto que no existe debe dar 404 y el mensaje Requested item not found.

      

    

    

      
Reto 3 · 401
Un login con contraseña incorrecta debe dar 401 y error: Unauthorized.
